# Road planning and map dispatch

Office dispatch can open **Routes → Map and road planning**, verify each service entrance using longitude/latitude and a source note, and view actual pins. Changing an address clears its verified pin automatically. A street basemap requires a licensed HTTPS XYZ template and attribution through VITE_MAP_TILE_URL / VITE_MAP_ATTRIBUTION. Without a configured basemap the map explicitly shows geographic pins on a blank background; it does not fabricate street data.

Owners/managers verify a truck's loaded height, width, length (centimeters), capacity gross weight and heaviest axle weight (kilograms). This initial provider workflow supports non-hazardous rigid trucks without trailers. Dispatch verifies trip start/end depot coordinates and supplies a departure time on the route's service date in the company timezone. Device-local departure input is converted to an absolute instant.

The server adapter implements Amazon Location Geo Routes v2 **OptimizeWaypoints** and **CalculateRoutes** with Truck travel mode, actual road geometry, traffic, loaded dimensions and applicable weight parameters. Contracts/endpoints/units were checked against the official @aws-sdk/client-geo-routes 3.1164.0 generated service models downloaded from the npm registry. API-key REST authorization uses the documented key query parameter; no invented AWS identity or SigV4 credentials are used. TLS verification, inherited proxy settings, timeouts, response-size bounds and redirect rejection remain enabled. Provider errors are sanitized so request URLs/keys cannot appear in office responses.

Configure ROUTING_REGION (a supported standard commercial AWS region) and ROUTING_API_KEY securely in deployment settings. Allow the exact regional host routes.geo.REGION.amazonaws.com in the environment network policy. The API key needs only the required Amazon Location route actions and appropriate provider restrictions. Never put this server credential in a VITE_ or EXPO_PUBLIC_ variable or in chat. Provider requests can incur charges: a saved-order road preview makes one CalculateRoutes request; an optimized preview also makes one OptimizeWaypoints request. No live provider request has been made or verified in this environment. No environment draft was changed or published for this feature.

A preview is limited to 1–20 already saved, unstarted stops. It records the route, stop versions, coordinates, truck profile and departure/depot inputs before making external requests outside the database transaction. Request retries return the existing preview rather than making another billable request. If a process stops mid-request the preview stays pending; dispatch must explicitly request a new preview after reviewing its state. There is no automatic billable retry.

Responses must contain every stop exactly once, zero impeding constraints, a Truck/Vehicle leg for every segment, complete road geometry and nonnegative distance/time. All route/leg notices currently fail closed, including informational notices: review provider responses in a controlled integration acceptance environment before expanding supported cases. Ferries/intermodal legs are unsupported. Linked dependent work supports road preview in its saved order; automatic resequencing is deliberately blocked until the provider's numeric precedence contract is independently verified. This avoids guessing dependency indexes.

Preview application is an explicit action and rechecks the exact route, stop versions/status, service pins and truck profile in the same transaction as resequencing. A started stop, changed assignment, changed pin/profile, expired preview or stale route blocks application without partial writes. Preview lifetime is 30 minutes. Application only changes route stop order and route version; order prices and assignments retain their saved values.

Road duration is estimated driving time. A separate timing table now adds saved service durations and arrival-window waiting when verified per-leg summaries are supplied; see SERVICE_TIMING.md. Breaks and facility queues remain excluded. This is an office planning aid, not installed turn-by-turn truck navigation or a guarantee of legal access. Drivers must observe posted restrictions and site instructions. Real provider, licensed tile rendering, snap quality, local restrictions, live time-dependent traffic after stops, larger route sizes, hazardous cargo/trailers and physical-device acceptance remain open.

Automated coverage uses deterministic provider fixtures and isolated PostgreSQL schemas, plus a real Chromium/emulator workflow for pin editing and the unconfigured state. These tests prove application validation and transaction behavior; they do not prove the provider's live routing quality.
